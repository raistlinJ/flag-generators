## Generators whose authoring id was already lost

40 of the 147 generators have a numeric `id` (and directory name) below. Those
packs were exported from an already-installed copy and then reimported, so the
install-time id rewrite had already overwritten the authoring identifier before
this repository existed. `.coretg_pack.json` recorded that numeric value as the
"source" id, and neither `_packs_state.json` nor the manifests retained the
original.

They are left numeric deliberately. A readable slug could be derived from each
manifest's `name`, but it would be a new identifier invented here rather than the
original, and it would look authoritative in a way a bare number does not.

Affected packs:

| pack | numeric / total |
|---|---|
| `flag_generators/archives` | 5/7 |
| `flag_generators/hashes` | 5/7 |
| `flag_generators/text` | 5/10 |
| `flag_node_generators/cache` | 5/7 |
| `flag_node_generators/database` | 5/7 |
| `flag_node_generators/dns` | 5/7 |
| `flag_node_generators/mail` | 5/7 |
| `flag_node_generators/smb` | 5/6 |

If you later recover the original packs, renaming these directories and their
manifest `id` is safe: ScenarioForge assigns its own numeric id on install, so
nothing downstream depends on the authoring value being stable.
